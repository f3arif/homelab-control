The source worker first examines completed, present files in the configured TorBox account. If absent, it requests stream **metadata only** from the owner's existing Comet configuration, extracts torrent hashes, checks TorBox cached-file metadata in bounded batches, and ranks exact title/year 1080p files with a known codec and size <=9GB, preferring 3–5GB. At most 500 metadata results / 200 hashes are examined. Larger-than-5GB fallback is excluded when that scan is incomplete. It never opens addon playback URLs. The chosen hash is added with TorBox `add_only_if_cached=true`, `allow_zip=false`, `seed=3`; there is no uncached acquisition. Fresh account inventory must confirm hash, concrete torrent/file IDs, name, exact size, completion and safety flags before a job is authorized. Provider outages/no matches remain visible and do not become false “downloading” states. An ambiguous add response is never retried automatically.

The automatic authorization record identifies the explicit finalization request and owner and binds the concrete file. It does not synthesize a human “yes” reply. Exact-file manual review APIs remain available for compatibility when automatic mode is off. The worker revalidates provider identity, writes an exclusive `.part`, checks exact length, SHA256 and ffprobe video dimensions/codec, then publishes without overwrite. Downloaded, indexed/available and observed playback are distinct. Queued source checks and approved transfers recover after restart; interrupted transfers are marked failed with files preserved. Historical saved choices without an explicit download request are never replayed into the queue.
